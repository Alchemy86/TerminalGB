# Audio-capture baseline: FNV-1a64 of the 16-bit interleaved PCM stream.
# A changed hash means the emulator now produces different samples for the
# same ROM — inspect the WAV in target/testrom-artifacts/audio/ and re-bless
# deliberately with:
#
#   UPDATE_AUDIO_BASELINE=1 cargo test --release --test audiocapture
#
# These hashes are MODEL-dependent: the fixtures boot whichever console
# the cartridge header asks for (dmg_sound is a DMG cartridge, so a DMG),
# and a different boot state shifts the sample stream. `GB_MODEL=cgb`
# reproduces the pre-DMG-mode numbers. The ROM verdicts pinned per
# fixture below are what actually asserts accuracy; the hash only pins
# "the samples did not change".
#
# They are PICTURE-MODE dependent too, for the same reason: the mode
# decides which cycle the cartridge reaches its APU writes on. This
# file is scored in whichever mode is the DEFAULT, which since
# 2026-08-20 is `identical` — see docs/picture-modes.md. `dmg_sound`
# reads HASH:fcb42a26ad26c1a5 under `GB_PPU=standard`, which is the
# value that stood before the flip.

# `tone440` moved once, deliberately, when the post-boot machine state landed
# (Mooneye `boot_hwio`): the boot ROM leaves channel 1's enable flip-flop SET,
# so the tone ROM's own `NR14` trigger is now a *re-*trigger and takes the
# shorter `SQUARE_RESTART_SPEEDUP` path. Confirmed to be that and nothing else,
# by comparing the two WAVs rather than by assertion: RMS 0.2467 and peak 0.267
# are identical to four decimal places, and every zero crossing in the stream is
# displaced by the same −0.047 samples (≈ one M-cycle). Same tone, same level,
# one M-cycle earlier. The reported "dominant" moved 440.0 → 438.0 Hz because
# the estimator counts crossings in a fixed 0.5 s window and the shift drops one
# — the pitch itself did not move. It has not moved since, the default picture
# mode flip included.

# `blargg/dmg_sound` moved once, on 2026-08-20, when `identical` became the
# default picture mode. Judged the same way — by the properties, not the hash —
# and every one of them is byte-identical either side: 1,625,088 samples, RMS
# 0.0265, peak 0.283, 96.8 % silent, max step 0.3333, dominant 480 Hz, and the
# ROM's own verdict still `01:ok .. 12:ok  Passed`. At sample level **9,788 of
# 3,250,176 samples differ (0.30 %), every one of them after 80.8 % of the
# capture**, peak identical at 9284 and RMS 867.916 → 867.932 on the raw 16-bit
# stream. That is one late sub-test's channel retriggering a few cycles earlier
# because mode 3 is no longer a fixed 172 dots — not a synthesis change, which
# would move the level, the pitch or the whole stream.
