# SCORED WITH THE `fast` PPU ENGINE (GB_PPU=fast).
# Re-bless with: UPDATE_EXTERNAL_BASELINE=1 make test-external
# The other engine produces different numbers for the same ROMs — see
# docs/mealybug.md §7 — so re-blessing with the wrong target rewrites this
# file with the wrong machine's results.
#
# Mooneye GB baseline — the EXPECTED verdict of every ROM in the groups listed
# below, judged by **Mooneye's own criterion**: run to the `LD B,B` software
# breakpoint, then require the Fibonacci registers B=3 C=5 D=8 E=13 H=21 L=34.
# Nothing here is a hash of our own output; the value on a failing row is the
# register dump the ROM itself left behind.
#
# The ROMs are NOT vendored — they are Gekkio's, fetched at run time from the
# author's own prebuilt archive at the build id pinned in
# tools/fetch-test-suites.sh. `make test-external` fetches them and runs this
# gate (see docs/testing.md, "Gating the external suites").
#
# CI is green when reality matches this file and red on ANY change, in either
# direction — a row that starts PASSING is a change too. Re-bless deliberately:
#
#   UPDATE_EXTERNAL_BASELINE=1 make test-external
#
# Rows whose name ends in a machine — `-dmg0`, `-mgb`, `-sgb`, `-sgb2`, `-cgb0`
# or a single Gekkio compatibility letter (`-S`, `-A`, `-C`, `-G`, `-M`) — are
# written for that console and cannot pass on another, so this runner boots the
# one each names (see `model_for`, and `src/mode.rs` for the consoles). A suffix
# naming *several* machines (`-GS`, `-cgbABCDE`) is left on whatever GB_MODEL
# asked for.
#
# All nine are green now. The remaining reds are the mid-scanline PPU rows, which
# need the cycle-stepped renderer (docs/mealybug.md §7) and are red under both
# engines. Note the community's often-quoted 66-row denominator DROPS the
# named-machine ROMs; this file scores all 75.
#
# Measured with GB_MODEL=cgb.
