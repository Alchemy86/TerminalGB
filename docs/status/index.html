Two picture modes

The scores above are the default standard mode, which draws a whole scanline at a time. identical runs the real hardware pixel pipeline dot by dot, so a register written half-way along a line lands exactly where a Game Boy puts it. Both are gated in CI against their own baselines. Press P in the terminal, or set ppu = identical.

identical now loses no row to the default on any gate. What stands between it and being the default is only its cost, so the choice is yours to make per game: almost every cartridge produces byte-identical frames either way, and the ones that do not are the ones with a mid-scanline effect — a split status bar, a wobble, a parallax band.

The Mealybug number, in context

Three out of seventy-nine looks alarming until you see what everyone else scores. On the twenty-four rows the Shootout publishes:

It is not a suite a competent emulator sweeps. Passing a row needs a picture unit rebuilt to run pixel by pixel rather than a scanline at a time — that engine exists here and is the selectable identical mode, which scores four times as many rows. The default has not moved because identical costs about twice the CPU, not because it is behind on anything.

Abilities

The machine

  • DMG, Game Boy Color and Super Game Boy models
  • Cartridge mappers 1, 2, 3 and 5, with a real-time clock
  • Battery saves in the ecosystem's own format
  • Save states, versioned, portable to the browser
  • Optional user-supplied boot ROM
  • Two picture modes: standard, or hardware-exact identical

In your terminal

  • Kitty, Sixel, iTerm2 and half-block rendering
  • Shared-memory frame transport — 87 bytes a frame
  • Four upscalers, palettes, HiDPI correction
  • Runs in any terminal; degrades, never refuses

Sound

  • Full audio hardware emulation, 36 ms latency
  • Volume control that never touches emulation
  • Chiptune renderer — instructions in, real audio out
  • Music mode: ROMs as a shelf, with export

Linking

  • Two consoles on one cable, trade proven
  • BGB network protocol over TCP
  • Virtual trade partner — no second cartridge needed
  • Cable Club battles against the partner

Plugins

  • Live trainer view: party, stats, sprites, catch rate
  • Shiny hunting from Gen 1 hidden values
  • Battle control — start any battle from outside
  • AI agent substrate for autonomous play

Beyond the terminal

  • Virtual camera — appears as a webcam
  • Screenshots, recording, telemetry stream
  • MCP server: any Claude client can drive it
  • Embeddable core — one third-party dependency
  • Browser build, and a conformance action others can use

Known gaps, stated plainly

Mid-scanline picture timing

The real ceiling. Needs the pixel-by-pixel engine promoted to default, which costs two currently-passing rows until it is finished.

Nine Mooneye rows are other consoles

Machine variants we deliberately do not emulate. Pinned as failures on purpose rather than quietly dropped from the denominator.

Four SameSuite rows

Two target older Color revisions and a Game Boy Advance. One is unsolved by the suite author's own emulator, whose source says the logic behind it is still unclear.

One test must stay red

The Color memory-corruption defect does not exist in Color silicon, so real hardware fails that ROM too. Passing it would be the bug.
