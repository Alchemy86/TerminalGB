## `actions_help` — sent once, on the first snapshot

```
Reply with one JSON object: {"goal":"<one short sentence, the standing objective>",
"say":"<one or two sentences of commentary for viewers, plain English>",
"plan":[ up to 12 actions ]}
Actions:
{"do":"press","button":"a|b|up|down|left|right|start|select","times":1}
{"do":"walk","dir":"up|down|left|right","steps":1-24}
{"do":"goto","x":N,"y":N}   - walk toward a coordinate on this map
{"do":"advance_text"}       - press A through dialogue until it ends
{"do":"wait","frames":N}    - let an animation finish
The plan runs to completion locally and you are asked again when it finishes, fails, or the world changes unexpectedly. Prefer few, large actions. 'say' is read aloud to strangers watching a stream: no JSON, no file paths, no jargon.
```

## `screen_help` — sent once, on the first snapshot

```
READING THE SCREEN. `screen` is the game's own on-screen text, decoded from the tilemap — it is what a player sees, not a summary.
  screen.kind      what shape of screen it is, and so what A does:
    no-text         nothing on screen is text (the overworld, the title screen). An empty screen.text here is a fact, not a failed read.
    text            text but nothing asking for a button.
    dialogue        the game is waiting: press A (or advance_text).
    menu            a cursor is up: A chooses screen.selected.
    yes-no          a QUESTION. A answers it with whatever is selected.
    naming-keyboard A types a letter; START finishes the name.
  screen.text      the visible text, blank lines dropped, indentation kept so a two-column menu still reads as two columns.
  screen.selected  the exact item the cursor points at (on the naming keyboard, the single letter A would type).
  screen.trust     'ok' means believe screen.text. Anything else means it was WITHHELD and screen.text is empty: 'graphics-not-text' (artwork whose tiles overlap the font), 'still-redrawing' (read mid-transition), 'screen-off'. Do not treat an empty text as an empty screen when trust is not ok — look again.
  Sprites are NOT in screen.text. People, Poke Balls and other objects are drawn over the tilemap and do not appear here at all.
```
